# 第三方网页增强：排查经验与验证流程

这份流程来自 2026-11-26 的 Chat Navigation 跳转回退排查，适用于本项目后续的消息识别、虚拟列表、滚动和生命周期问题。具体实页结果见 [本次验证记录](navigation-live-verification.md)，实现细节见 [架构文档](architecture.md)。

## 这次为什么反复

扩展、ChatGPT 的底部跟随逻辑和虚拟列表都可能改变滚动位置。一次 `scrollTo` 返回、目标短暂出现，都不足以证明跳转完成。

| 现象 | 本次证据与结论 |
| --- | --- |
| 跳过去后又回到末尾 | 绕开扩展的失败恢复逻辑，单独调用滚动，仍观察到约 800ms 后回退。页面自身也在调整位置。 |
| 旧坐标指向别处、目录顺序变化 | 加载旧消息会改变滚动总高度和坐标原点。不同加载窗口的像素位置不能作为统一的历史顺序。 |
| 目标出现过，却仍报告找不到 | 目标可能在顶部加载期间短暂挂载；等待整个窗口稳定后再查找，会错过定位机会。 |
| 本地目录已经恢复，点击仍要等待 | 备份恢复的是预览和标识，网页仍需加载、挂载原消息。备份不是完整对话 DOM。 |

前期模拟测试主要覆盖了扩展如何识别消息、保存索引和调用滚动，没有充分覆盖网页自身的底部跟随、延迟挂载和坐标重排。因此，增加等待、修补坐标和身份别名虽能修复部分场景，却不能单独证明实页回退已解决。过早把测试通过当成问题解决，增加了构建、重载和返工次数。

后续应先建立真实页面的最小复现，再一次验证一个假设。模拟测试用于固定已经观察到的失败机制，并承担回归检查。

## 排查顺序

1. **确认运行的是哪份代码。** 检查 Git 分支和工作区改动、Chrome 加载的 `dist/` 路径、弹窗版本与功能开关。构建完成后重载扩展，再实际刷新目标 ChatGPT 标签页；只重开弹窗不能更新已注入脚本。使用“检查当前页”和 DevTools 的 Content scripts 确认连接，不凭版本号相同就认定代码已更新。
2. **固定复现条件。** 使用已授权的同一长会话，记录起点、目标条目、备份开关、窗口宽高、原生侧边栏及 DevTools 停靠状态。先复现“从末尾点击最早缓存问题，稍后又回退”，避免一开始同时改导航样式和定位算法。
3. **区分失败阶段。** 依次判断：目标尚未挂载、身份无法确认、滚动容器错误、头部偏移错误、到达后被页面撤销，还是扩展主动恢复了原位置。必要时用可撤销的最小 DOM 滚动实验区分页面行为与扩展行为，不修改 React 私有状态、不调用未公开后端接口。
4. **建立有限观测。** 对照目标身份匹配结果、挂载数量、`scrollTop`、`scrollHeight`、视口高度和目标矩形。观察操作前、到达时及延迟后的状态。约 800ms 才发生的回退，不能用一次即时截图排除；可在约 2 秒和 8 秒再检查。
5. **只改变一个因素。** 例如分别比较数值滚动、真实用户消息的 `scrollIntoView`、方向滚动意图及加载等待策略。保留成功与失败的条件和结果，再决定实现方案，避免用越来越长的超时掩盖未解释的行为。
6. **补回归模型，再复测实页。** 模型至少覆盖底部跟随、延迟挂载、旧消息前插与坐标重置、节点复用、身份升级、晚到的备份读取，以及手动接管和销毁。现有入口是 [历史导航测试](../tests/chat-navigation-history.test.ts)、[DOM 生命周期测试](../tests/chat-navigation-dom.test.ts) 和 [备份测试](../tests/navigation-backup.test.ts)。

DevTools 会改变可用宽高和消息换行，从而改变滚动坐标。记录停靠方式，避免在同一比较中无意切换布局；结束前还需关闭 DevTools，在正常浏览布局下复测。

诊断应限时、可清理，并优先输出计数、布尔值和几何信息。不要把原始消息、完整 HTML、问题预览或真实标识写入项目日志、测试夹具和验证文档。复现数据使用脱敏结构。Console 的粘贴保护或 CSP 拦截不是脚本执行成功的证据；不要为排查关闭这些保护，可改用现有弹窗诊断和 Elements 查看结构。

## 固定验收流程

在有足够导航空间的长会话中执行下表。逐项记录“通过、失败、未验证”，不把未执行的场景写成通过。比较的是同一消息及阅读偏移；加载前后数值坐标不同可以是正常现象。

| 场景 | 操作和通过条件 |
| --- | --- |
| 末尾 → 最早 | 点击最早条目，确认原消息身份和头部留白；等待后仍停留在该消息，没有回到起点。 |
| 最早 → 中间 → 最新 | 依次选择远处条目，确认不会跳到邻近问题或同名问题。已挂载目标应立即移动；未挂载目标允许显示加载状态，但最终必须验证身份与稳定落点。 |
| 扫描与恢复 | 先记录阅读锚点及其视口偏移，再扫描历史。结束后回到同一消息、同一偏移；原有条目保留，目录没有重复或错序。延迟后再确认没有回退。 |
| 刷新与备份 | 在已启用本地备份的测试环境中刷新，确认目录恢复且顺序正确；点击后仍需校验实时消息。备份晚于页面末尾消息返回时，也不能把末尾排到前面。 |
| 用户接管 | 扫描或定位期间进行真实滚轮、触摸或滚动按键操作，自动操作应停止，不再把用户拖回旧位置。显式“停止并返回”则尝试恢复阅读锚点。 |
| 生命周期 | 操作期间切换会话或关闭 Chat Navigation，旧操作不得滚动新页面，导航 UI 和临时监听应清理，颜色功能保持独立。 |
| 布局与失败 | 正常浏览布局和 DevTools 布局分别检查。目标已删除、分支已变或无法确认时，应显示失败并区分精确恢复与近似返回，不能把邻近消息当成功。 |

验证备份关闭和清除功能时，使用独立测试数据或自动化存储模拟；不要为了验收删除用户现有备份。没有实测条件的 Project/custom-GPT 会话、流式回复、编辑分支和慢网络等场景，应明确留在“未验证”列表。

## 提交前检查与证据

从仓库根目录运行：

```sh
npm run typecheck
npm test
npm run build
git diff --check
```

`build` 包含类型检查；单独的 `typecheck` 命令用于快速定位类型错误。文档修改还应确认新增链接可达、文件路径存在，且验证记录没有真实对话内容。

| 验证层级 | 能支持的结论 |
| --- | --- |
| 类型检查和构建 | 类型关系通过检查，能生成扩展产物。 |
| 自动化测试 | 已建模的 DOM、时序、存储和生命周期场景通过。 |
| 真实页面操作 | 指定浏览器、会话、布局和已执行步骤下，观察到了所记录的行为。 |

交付时分别报告这三层结果，并写明未覆盖范围。实页记录应包含日期、测试环境、复现起点、操作步骤、延迟观察、恢复结果和剩余限制；不需要保存对话文字和真实 ID。实现成功调用了滚动方法、扫描到达当前可滚动边界，都不能推导出完整服务端历史已经加载。

提交前审阅待提交文件和 diff，只包含本轮授权范围。按用户要求执行本地 commit；push、merge 等发布动作按单独授权处理。
